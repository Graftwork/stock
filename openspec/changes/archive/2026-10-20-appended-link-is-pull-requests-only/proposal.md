## Why

`foundation`'s *Coding Session Links Are Not Disclosed* says the platform
appends a link to "a pull request or issue body" when the agent opens one, and
that the agent SHALL NOT open pull requests. The rule covers pull requests
only, so the premise claims more than the rule answers. A reviewer on the
previous change raised exactly that gap, and the evidence now settles which
way to close it: the premise is wrong for issues, not the rule too narrow.

Measured in October 2026, by reading each body straight after it was created
(the body, not its edit history, which the sessions' proxy does not serve):

- An issue created with the GitHub tool: body unchanged. Two of two, one in
  `stock-archive` and one in `sorting-office`; in the second, `created_at`
  equalled `updated_at`, so no later edit either.
- An issue created through the REST API with `gh`: one of one got the footer
  `_Generated by [Claude Code](https://claude.ai/code)_`, which names no session.
- Pull requests, for comparison: every body read back straight after creation
  carried the footer with a `session_…` id. That is 8 of 8: two on Stock, two
  on `stock-archive` (one made through the REST API) and four on
  `sorting-office`. The owner also found the footer in the edit history of all
  six Stock pull requests the agent opened; the agent had read only two of
  those bodies before editing them.

Only creation was tested, not issue comments or updates, and the samples are
small.

## What Changes

- The second paragraph of *Coding Session Links Are Not Disclosed* says "a pull
  request body" where it said "a pull request or issue body". The rule and
  both scenarios are unchanged, so scenario ids, test markers and the declared
  gap keep working.
- [Stock ADR 0018](../../../../docs/decisions/stock-0018-owner-opens-agent-pushes.md)
  records the issue measurements, and its Consequences stop describing the
  spec as still wrong.
- Two claims found wrong while preparing to publish are corrected in the same
  change: `stock-0011` links to a skill folder that does not exist in
  `sorting-office`, and `docs/GOING_PUBLIC.md` step 7 says an agent cannot
  check a repository's ruleset.
