## Why

*Coding Session Links Are Not Disclosed*, as first archived, promises more
than a repository can keep. Its scenario says that when a coding agent opens a
pull request or issue, "its body … contains no link to the session". The
accompanying house rule in `CLAUDE.md` says a repository's own instructions
take precedence over the platform's per-session default, and calls itself
"the line that does it".

That holds for text the **agent writes**. It does not hold for a link the
**platform's tooling appends** to a pull request body after the agent has
finished writing it. Measured in this repository, in a session whose
instructions no longer asked for a session link (see the `attribution` setting
in `.claude/settings.json`): two draft pull requests opened through the GitHub
tool ([`Graftwork/stock#36`](https://github.com/Graftwork/stock/pull/36) and
[`#37`](https://github.com/Graftwork/stock/pull/37)) both came back with
`_Generated by [Claude Code](…/session_…)_` at the end of the body. In the
second, the agent had written a plain footer itself; the tool replaced it with
the session-link version. Nothing the agent writes, and so no repository
instruction, can prevent that.

A requirement that says "SHALL" about something no instruction can deliver is
worse than a narrower one: a reader assumes it is being kept.

## What Changes

**MODIFIED** `foundation` → *Coding Session Links Are Not Disclosed*:

- The requirement is scoped to what a repository can actually govern: the
  **text an agent writes** for a pull request or issue, and the **commit
  message**. It states outright that a link appended by platform tooling after
  the agent has written the body is outside it.
- The pull-request scenario keeps its title and id
  (`a-pull-request-or-issue-contains-no-session-link`); its WHEN/THEN is
  reworded to be about the text the agent writes. Its declared gap in
  `pyproject.toml` keeps the id and gets a reason that says why: the suite
  cannot observe what an agent writes, and a tool-appended link is outside any
  repository rule.
- The commit-message scenario is unchanged.

Supporting changes outside the spec: the `CLAUDE.md` house rule loses "this is
the line that does it"; the `[Unreleased]` CHANGELOG entry is rewritten to say
what the change does and does not stop, and how it relates to the
`attribution.sessionUrl` entry beside it; and `main()` in
`scripts/check_no_session_link.py`, the part that actually runs at commit time,
gets tests (it had none — `check()` was covered, `main()` was not).

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `foundation`: *Coding Session Links Are Not Disclosed* is narrowed to what a
  repository can govern. A project that adopted the earlier wording loses no
  promise it could actually keep.

## Impact

`openspec/specs/foundation/spec.md` (by archive), `pyproject.toml` (the one
declared gap's id and reason), `tests/test_check_no_session_link.py`,
`CLAUDE.md`, `CHANGELOG.md`, `docs/UAT.md` (agent-run records).

Touches `openspec/specs/`, `tests/`, so it takes the full OpenSpec route under
`docs/RELEASING.md`. This lands in the same pull request
as the change it corrects, before either reaches `main`, so no released
version ever carries the wider wording.
